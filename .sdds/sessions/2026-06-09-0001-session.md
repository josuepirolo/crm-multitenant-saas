## O que foi feito

### Importação em lotes automáticos (sem limite de linhas)
- `extractImportPreview` passa a retornar `totalDataRows` (contagem total de linhas de dados da planilha)
- `parseContactImportFile` aceita `options?: { offset?: number; limit?: number }` — processa apenas o range solicitado; o limite de 2000 linhas com erro foi removido
- `importContactsAction` lê `offset` e `chunk_size` do FormData; rate limit aplicado apenas no primeiro lote (`offset === 0`); audit log idem
- `useContactImportViewModel` orquestra o loop de lotes: calcula `chunks = ceil(totalDataRows / MAX_IMPORT_ROWS)`, chama `importContactsAction` N vezes sequencialmente, agrega `created`/`skipped`/`errors` de todos os lotes; expõe `currentChunk`, `totalChunks`, `processedRows`
- `ImportContactsDialog` exibe barra de progresso animada (Framer Motion) + contador "X / total" durante importação em lotes; botão mostra "Lote N/M" enquanto processa; `Voltar` desabilitado durante importação

## Decisões tomadas
- Re-parse do arquivo a cada lote (sem cache/sessão): custo aceitável para arquivos ≤5MB; evita estado server-side complexo
- Duplicatas cross-lote: não detectadas pelo parser (cada lote tem seu próprio `seen`); o constraint único do banco rejeita silenciosamente — comportamento correto
- Rate limit somente no lote 0: uma importação de 10k linhas (5 lotes) não consome 5 tokens de rate limit
- Audit log somente no lote 0: uma importação = um evento de auditoria
- `MAX_IMPORT_ROWS` (2000) mantido como tamanho de lote, não mais como limite hard

## Riscos / pendências
- `totalDataRows` é estimativa via `worksheet.rowCount - 1` — pode incluir linhas vazias no final do arquivo (ExcelJS); número real de linhas importadas pode ser ligeiramente menor
- Teste manual com arquivo >2000 linhas não feito
- Se uma chamada de lote intermediária falhar (rede/timeout), a importação para naquele ponto; não há retry automático nem transação distribuída — usuário recebe erro parcial
