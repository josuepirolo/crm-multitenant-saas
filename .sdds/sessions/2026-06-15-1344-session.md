## Contexto

Após `npm run dev`, o usuário reportou **404 em `/dashboard`** (e redirect de `/` também falhando).
Sessão anterior (`1338`) tinha adicionado rotas `/whatsapp/*`.

## O que foi feito

### Diagnóstico
- Rota `src/app/(dashboard)/dashboard/page.tsx` **existia** — não era rota ausente no código.
- `npx next build` falhou em TypeScript com `.next/dev/types/routes.d.ts` **corrompido**:
  entrada truncada `pp/conexao` em vez de `"/whatsapp/conexao"` (manifest Turbopack inválido).
- Com cache corrompido, o dev server respondia **404** para rotas válidas (incl. `/dashboard`).

### Correções
1. Removido `"use server"` de `src/lib/whatsapp/workspace-has-integration.ts` — é helper de
   Server Component (layout), não Server Action exposta ao client.
2. Apagado `.next/` e rebuild: `next build` **OK** — 33 rotas incl. `/dashboard`, `/whatsapp/*`.
3. Dev server limpo: `/dashboard` → **307** para `/login` (sem auth), não 404.

### Workaround operacional (dev)
Se **404 em massa** após adicionar rotas com Turbopack: parar `next dev`, `Remove-Item -Recurse -Force .next`, reiniciar.

## Decisões tomadas

- Helpers server-only chamados só de RSC **não** devem usar `"use server"` no topo do arquivo.
- Não commitar pasta `.next/` (já no `.gitignore`).
