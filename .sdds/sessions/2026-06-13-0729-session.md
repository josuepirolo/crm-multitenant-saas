## O que foi feito

Definido o **design v2 (BFF) da tela `/settings/integrations`** (R-001), a partir da doc de
contrato do backend WA (`backend_zapi/frontend-whatsapp-integration.md`, entregue pelo usuário).

A v1 já commitada (`dc76c2e`) era **somente-leitura via RLS** sobre `workspace_integrations` — não
entrega status real, QR Code nem perfil/privacidade, porque `wa_*` não é legível por RLS ao membro.
A doc do backend revelou que o backend WA expõe uma **API REST própria** autenticada por JWT Supabase
(`require_auth`, `sub` = `wa_tenant_members.user_id`), destravando esses dados sem dar `SELECT` em
`wa_*` ao membro. Usuário escolheu (AskUserQuestion) **"pular pra v2 (BFF)"**.

Entregue nesta sessão:
- **ADR-006** (`decisions/ADR-006-bff-wa-backend-management.md`) — CRM consome o backend WA como BFF.
- **Spec v2** — §11 anexada a `specs/settings-integrations.spec.md` (versão 1.0 → 2.0), com
  faseamento v2.1 (status/QR) → v2.2 (restart/disconnect) → v2.3 (perfil/privacidade).
- **Harness v2** — 12 cenários `BFF-01..BFF-12` em `harness/settings-integrations.harness.md`.
- **Infra contract-independent (código, `tsc --noEmit` limpo):**
  - `.env.example`: nova `WA_BACKEND_URL` (server-only, sem `NEXT_PUBLIC_`).
  - `src/lib/wa-backend/client.ts`: client HTTP genérico que repassa o JWT do usuário como Bearer,
    timeout via AbortController, erros tipados (`WaBackendNotConfigured`/`HttpError(status)`/
    `Unreachable`), `getUserAccessToken()`, `isWaBackendConfigured()` — **nunca loga token/QR/credentials**.
- **INDEX.md** atualizado (ADR-006 + status v2 + harness apontado).

## Decisões tomadas (resumo do ADR-006)

1. **BFF** — browser nunca chama o FastAPI; tudo via Server Action do CRM.
2. **Auth por repasse do JWT do próprio usuário** (sem secret novo, sem `service_role`); autorização
   final é do backend WA (`wa_tenant_members`).
3. **Base URL** em `WA_BACKEND_URL` (server-only); ausência = feature degrada com erro genérico.
4. **`wa_tenant_id`/`instance_id` validados no servidor** contra `workspace_integrations` (anti-IDOR).
5. **RBAC do CRM por cima**: leitura → `settings:view`, mutação → `settings:edit` (reusa módulo
   `settings`; não existe `PermissionModule` "integrations").
6. **Erros traduzidos** (401/403/409/5xx/timeout) sem vazar corpo/stack/token.
7. **Gap conhecido**: membro do workspace CRM ≠ `wa_tenant_members` no backend → 403 legítimo; fechar
   é trabalho do backend WA.
